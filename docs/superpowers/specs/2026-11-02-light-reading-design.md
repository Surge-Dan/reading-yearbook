# 轻量蒸馏与可选报告精华

用户已确认：年度报告是核心，蒸馏是可选的读书笔记，不再要求生成报告前必须完成一本蒸馏。

## 本次实现

1. 无蒸馏包也能通过构建器、自动采集入口与交付入口生成真实报告；显式提供的坏包、被篡改包与 sample/real 混用仍拒绝。没有精华时隐藏对应阅读区与导航，不出现上传或任务控件。
2. 助手新任务默认走轻量流程：正文解析与有界分段阅读，最后一次综合生成概览、3–5 个核心观点、至多 3 个启发／做法、至多 3 条可靠金句和短书评。段落可少，不凑栏目；正文约 1200–1800 字为写作参考，设合理上限防止再生成知识库。
3. 书名输入仍先确认身份、读取有限公开资料，再一次综合生成同样的短稿。小说／传记不强造方法，人物、情节与底色可融入观点和启发。
4. 默认不调度能力卡、RIA、逐项覆盖对齐、基线／压力演练及独立书评调用。保留历史引擎以兼容旧接口／缓存，但不向用户增加模式选择。
5. 共享结果包、原文引用核对、资料范围、取消／会话权限、缓存身份、预算确认与原子发布继续保留。短稿不能冒充全文逐句核验或临床／任务效果验证。书名资料不冒充上传全文。
6. 网页、Markdown、独立 HTML、分享图均使用同一短稿。年度主体、字体、图表、封面策略不调整，旧结果不自动删减或改写。

## 执行与验收

- 先写报告无包生成及轻量流程的行为测试，确认现有行为失败，再实现。
- 验证无包报告三入口、坏包保护与真实／示例隔离；轻量分段不漏末章、来源和长度检查、断点复用与取消；新任务默认路由；书名来源边界。
- 运行相关回归与本地浏览器检查：无包报告可浏览导出，有包显示五类短稿；旧结果仍可读。使用受控短文检查工程链路，不宣称完成与上游的真实速度／质量对比。
- 独立窄范围代码审查；更新 Skill 文档及资源清单，测试后提交并推送 main。私人书本、结果和缓存不提交。
